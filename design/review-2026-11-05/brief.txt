Build ONE self-contained index.html that draws the phone screen at exactly 412x892 CSS px (Android dp), status bar included. No device frame, no page around it, no presentation chrome: the screen fills the viewport edge to edge.

Screens by URL hash, each rendered on load (I screenshot each one headless at 412x892): #pairing, #list (default), #drawer (list with the drawer open), #conversation (idle), #run (a run going: working line, Stop and Steer), #transcript (the run's transcript bottom sheet open over the conversation), #tray (an image waiting in the message box), #approval (an approval waiting in the conversation), #settings, #new (a new, empty conversation), #loading (the list right after launch, before the conversations arrive).

GOAL: review the shipped screens and propose a polished version of each: keep the app's identity, structure and the decisions below, fix the problems listed and any others you find. It will be rebuilt in Compose, so everything must be buildable natively: flat fills, 1 dp hairlines, square corners, the tokens below; no blur, no glass, no shadows except the drawer scrim and the bottom sheet's, no web-only effects, no colours outside the list.

FIXED (the owner decided these; keep them):
- Light theme only. Fonts: Inter (UI) and JetBrains Mono (data: ids, times, counts, commands, hostnames), from Google Fonts. NOT the design system's Space Grotesk / Outfit / Archivo.
- Paper ground #F2F2F2 with Endfield's thin contour lines in sunken #E5E5E5 behind lists and the chat.
- Top bar: 56 dp under the status bar, steel gradient left to right #666666 -> #35373C -> #191919, text #E9E9E9. List: menu (hamburger) left, title "Chat", right: link state (LINKED / OFFLINE, mono caps) and the filter icon. Conversation: back arrow, title + a small subtitle (source), the model picker (outlined, mono "opus-5-5") and the more (three dots) menu. Under a conversation's bar Endfield's title rule, 3 dp: magenta #FF1AAC 56 dp, yellow #FFFA00 72 dp, then green #00FFA2 to the edge.
- Navigation: a modal drawer, 316 dp, on #666666; relay status at its top (TRISMEGISTUS, host + linked), the sections as 52 dp rows, the selected one a white card with a 1.5 dp yellow #FFFA00 outline and ink text; the device line (name · paired · role) and the settings gear at its foot. For now it lists ONLY Chat (GitHub, News, Agents, Jobs and Commands come later: do not add them).
- List: kind tabs as bare icons with counts (App, Telegram, Terminal, More), the selected one marked by a 2 dp bar; a header like `APP // 13` with PINNED FIRST at its right; a filter field; compact rows (title, pin or lock icon, mono meta like "pinned · 36 min", RUN / APPROVAL marks with a timer); a yellow square FAB with an ink outline for a new conversation.
- Conversation: message labels `YOU // 09:48`, `HERMES // 09:49`, `YOU // STEER // 09:49` (label role, caps); your messages are white cards with a hairline outline; Hermes' answers are plain text on the paper, inset 12 dp (no bubble, no bar); tool calls are folded rows; code blocks are separate blocks with a copy button; a run's commands are summed up in one marker row that opens the transcript as a bottom sheet.
- Message box (agreed frame "04c"): ONE row: attach (paperclip), camera, the multi-line field (grows to 6 lines, then scrolls), Send as a yellow square icon with an ink outline. During a run Stop (red outline) and Steer (yellow square, arrow up-right) replace Send. Selected images sit in a tray above the row. Icons stay on the field's last line.
- Approval: a banner in the conversation with the command (mono), the reason, and Once / Session / Deny in words (never "always"). Once is the only yellow on screen while it shows; Session plain; Deny red outline; Steer and Send are demoted to plain while it is open.
- One yellow primary per screen. Yellow and magenta are fills and marks, never text on light grounds. Obvious actions are icon-only (send, stop, copy, new); consequential ones keep their words (Once, Session, Deny, Pair, Unpair).

PROBLEMS SEEN in the screenshots (fix these):
1. #loading: right after launch the list shows the empty state "No conversations from the app yet" with a New conversation button for a second or two, then the list replaces it. Show a loading state instead.
2. #run: the conversation's subtitle reads "app · run run_" (a cut run id). Show the run's state, or nothing.
3. #run: the working line says "WORKING 00:00 · 1 command" and the marker "1 COMMAND 0.0 s" while the command is still running: no live sense of progress.
4. #run vs #conversation: the same turn reads differently live (">_ 1 COMMAND ... transcript" marker) and after a reload ("> terminal sleep 25" folded tool row). Make them one consistent row.
5. #transcript: the title shows a cut run id ("TRANSCRIPT // RUN RUN_"); the running entry is a loud orange bar; the COMMANDS / ALL TOOLS switch adds little (the owner dropped such filters on the Mac).
6. #tray: the remove button is a large black square over a third of the thumbnail; the caption "1 OF 4 IMAGES // RESIZED TO 2048 PX, LOCATION REMOVED" is long and shouty.
7. #drawer: one item on a tall grey column reads empty; the list behind shows through on the right without a clear scrim.
8. #settings: rows are uneven (some with a subline, some not), the custom switches read heavy, and "Push: not set up yet" gives no next step.
9. A message just sent shows "YOU" without a time until the conversation reloads; give it a time (or "sending").
10. #new: a new conversation is a blank page with no hint of what to do.
11. #pairing: the QR viewfinder dominates; the paste-code path and the relay URL below read as an afterthought, and the command to get a code is cut off.
